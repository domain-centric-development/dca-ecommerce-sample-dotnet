# CAT-04's test stage hit the round limit, but its last gate run passed every content check. Accept the stage?

## Question

The test gate refuses CAT-04 on one check only, `rounds`: "3 rounds without convergence — stop and escalate". In
the same run every other check passes: 7 tests mapped to 7 criteria, all found, `dotnet build` succeeds, all 7 tests
green, and `tests-kept` holds. The earlier rounds did not fail on the tests. They failed because the process running
the gate had no `dotnet` on its PATH (`/bin/sh: dotnet: command not found`, noted in `tasks/CAT-04/tests.md`). Does
the test stage count as done for CAT-04?

## Evidence

- `tasks/CAT-04/.gate-test.txt` — one `gate:fail` besides the summary line: `rounds` (line 5). Everything else is
  `pass` or `note`.
- `tasks/CAT-04/.verify/journal.tsv` — the test gate refused at 10:27:25, 10:28:02, 10:28:54 and 10:32:03.
- `tasks/CAT-04/tests.md` `## Notes` — rounds 2 and 3 were refused because `compiles` and `tests-green` could not
  find `dotnet`. The gate's latest run finds it (`compiles` passes).
- Not checked in any round: whether each break under `tasks/CAT-04/breaks/` turns its test red. The gate report has
  no break line, and this session was not allowed to apply the patches.

## Options

1. **Accept the test stage.** The failures that ran up the count came from the environment, and they are gone now.
   The tests and the table are unchanged, so the story moves on to build (in adopt mode, the build gate checks).
2. **Reset the round count and run the test gate once more**, so it also reports on the breaks before the stage is
   accepted.
3. **Re-plan CAT-04.** Only if the human sees a problem with the tests themselves. The gate report shows none.

## Recommendation

Option 2 if the gate checks breaks at this stage: one more run, with nothing changed, costs little and settles the
one unverified point. Otherwise option 1.
