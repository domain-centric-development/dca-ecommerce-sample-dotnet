# The catalogue's page title: "Product Catalog" as the story says, or "Products" as the shop shows?

## Question

CAT-01 is `status: adopted` — it claims to describe behaviour the shop already has. Scenario
`catalogue-page-heading` says the catalogue's page title is "Product Catalog". The shop renders the
browser tab title "Products". The heading "Our Products" and the breadcrumb "Home / Products" match.
Adopt mode plans no production change, so a scenario the code does not show cannot be adopted as
written. Which is the agreed behaviour?

## Evidence

- `src/DcaShop.Web/Views/Product/Catalog.cshtml:2` — `ViewData["Title"] = "Products"`.
- `src/DcaShop.Web/Views/Shared/_Layout.cshtml:9` — `<title>@(ViewData["Title"] ?? "domaincentric.commerce")</title>`:
  no prefix or suffix, so the tab reads exactly "Products".
- `src/DcaShop.Web/Views/Product/Catalog.cshtml:3-8` — breadcrumb "Home / Products", `<h1>Our Products</h1>`
  (these parts match the story).
- AGENTS.md: the views mirror the Java sample's Pug templates one to one, so what the title should be is
  also a question for the Java twin.
- No existing test asserts the catalogue's title (grep over `tests/` for `Product Catalog` and the title: no hit).

## Options

1. **The story is wrong: the title is "Products".** Correct the scenario in `CAT-01.md` to "the page title is
   'Products'". The story stays adopted; nothing is built.
2. **The code is wrong: the title should be "Product Catalog".** The story is then not an adoption: it leaves
   `status: adopted` and is released as a change (one line in `Catalog.cshtml`, kept in step with the Java
   template), or the title part moves into a separate change story and CAT-01 keeps only the heading and
   breadcrumb.
3. **Drop the title from the scenario.** Keep heading and breadcrumb only; the title stays unspecified.

## Recommendation

Option 1, unless the Java sample's catalogue template renders "Product Catalog" — in that case the two
samples already disagree, and option 2 (a change story, both samples in step) closes that gap. Check the
Java template before answering.

## Answer
answer: 2 — the code is wrong. The Java shop renders the catalogue's title "Product Catalog" (ProductCatalogPageViewModel); the .NET shop is brought in line by a change story of its own, catalogue-title, which CAT-01 depends on. CAT-01 stays adopted and is adopted once that story is delivered.
