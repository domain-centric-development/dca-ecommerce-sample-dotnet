# Architecture documentation

- [Context map](context-map.md) — generated by the architecture tests from the context attributes.
- [Strategic context map](../../product/domain.md) — designed and hand-maintained: relationship patterns and subdomain types.
- [Architecture decision records](adr/README.md).
- [Refusal wording](refusal-wording.md) — every sentence the shop refuses with, per failure type and page; the
  Java twin carries the same file, so the two shops can be compared line by line. A use case result never carries
  a sentence: `ChangePasswordResult` names the outcome and the broken `PasswordRule`, `ChangeProfileResult` the
  outcome (`EmailInvalid`, `DateOfBirthInvalid`, …), `ReduceStockResult` a `LineFailure` per line, and the page
  words them.
- The repository [README](../../README.md) explains the solution layout and which pattern lives where.

Rule-by-rule reference: `RULES.md` in the `DomainCentric.ArchRules` package (counts in its `rules.json`, ids `DCA-<SET>-<NNN>`).
