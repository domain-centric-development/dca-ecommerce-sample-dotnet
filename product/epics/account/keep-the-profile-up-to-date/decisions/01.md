# The story is adopted, but after a change of address the old address still logs in — how to go on?

## Question
The story has `status: adopted`: it claims every scenario is behaviour the shop already has. The test stage wrote a
characterization test per scenario; five are green, but `old-address-no-longer-logs-in` is red on today's code:
`ProfilePageTest.TheOldAddressNoLongerLogsIn` (`tests/DcaShop.IntegrationTests/ProfilePageTest.cs`) logs in with
"anna.schmidt@example.com" after the change to "anna.meyer@example.com" and gets `302` to the cart, not the login page
with "Invalid email or password".

Cause, read from the code: `InMemoryAccountRepository` hands out the stored instance
(`src/DcaShop.Account/Adapter/Outgoing/Persistence/InMemoryAccountRepository.cs:11`), so in `SaveAsync` the stored
account *is* the changed aggregate; the check `stored.Email.Value != aggregate.Email.Value` (line 39) is never true and
the old address stays in the `_byEmail` index (line 41 never runs). `FindByEmailAsync` with the old address then still
finds the account, and the password matches.

An adoption changes no production code, and a scenario the code does not show is not adoptable — so this stage may
not decide it.

## Options
- a: Take the scenario `old-address-no-longer-logs-in` out of this story and write it as a story of its own
  (status `ready`), which the pipeline builds: the test is already written and red, the fix is in the repository's
  index. This story is then adopted with five scenarios.
- b: Release this whole story as a normal story (status `ready` instead of `adopted`): the five green tests need a
  break each, the red one is the build's work.
- c: Fix the repository by hand as a `kind: task` first, then adopt the story with all six scenarios.

## Recommendation
a — the five scenarios are the shop's behaviour today and adopt as they are; the stale login is a defect with its own
red test, and a story of its own keeps the fix visible and reviewed.

## Answer
answer: a, as a story the pipeline builds — the Java shop is right (it adopted old-address-no-longer-logs-in as written). The .NET shop is brought in line by old-address-stops-logging-in, which this story depends on. This story stays adopted as written, all six scenarios.
