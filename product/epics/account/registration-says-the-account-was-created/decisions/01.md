# How may a story's new browser test pass `SharedScenariosTest` before the gate merges its scenario into `product/spec`?

## Question
The story's happy path needs a new browser test, `DcaShop.E2eTests.RegistrationE2eTest#TheHomePageARegistrationLeadsToSaysTheAccountWasCreated`,
titled "Registration says the account was created" (the scenario's key in words, as the test gate requires). The
production code is done, and both mapped tests are green. The build gate still fails on the required unit suite:
`DcaShop.UnitTests.Specification.SharedScenariosTest#EveryBrowserTestIsAScenarioOfThisShopsSpecification`
(`tests/DcaShop.UnitTests/Specification/SharedScenariosTest.cs:43`) requires every browser test's title to be
a scenario title in `product/spec/**/scenarios.md`. Only the gate that delivers a story writes `product/spec`, so
every story that adds a browser test fails at build until delivery, which it can never reach. This story is the
first one to hit it since 96e95f8 emptied the exception list. A stage may not change that existing test
(the plan does not list it), may not write `product/spec`, and may not misuse `TitledAfterTheSharedSpecification`.
Its doc comment says the list only shrinks, and line 45 would fail the day the scenario lands.

## Options
- a) `SharedScenariosTest` also accepts the scenario titles of the stories under `product/epics/**/story.md` that
  are not delivered yet (approved/running), so a browser test may run ahead of its spec by exactly one open story.
  This changes an existing test once and fixes it for every later story.
- b) The pipeline's build/tidy gates merge the plan's `## Spec delta` into a scratch `product/spec` before running the
  required suites. That is a change to the factory in `dca-marketplace`, not to this sample.
- c) Mark this one title as an exception for now (add it to `TitledAfterTheSharedSpecification` and reword its doc
  comment). The delivering gate would then fail on line 45 and need a manual removal, so this is not recommended.

## Recommendation
a): it is the smallest change that keeps the binding (a title must still name a scenario somewhere a person wrote
it), it is local to this sample, and the Java twin's equivalent check needs the same answer. With a), add the
test to this story's plan under `## Changed tests`, backed by this decision.

## Answer
answer: SharedScenariosTest also knows the titles of the stories not yet delivered (their `####` criteria, title = Title line else the key in words); the spec stays the only source for the Test-line and duplicate checks. Fixed on main in 2ea4aaa; nothing changes in this story — run the stage again as it is.
