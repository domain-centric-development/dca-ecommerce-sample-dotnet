# The page no longer shows the refusal texts this adopted story names — change the story or the page?

## Question

The story is `status: adopted`: it should describe behaviour the shop already has. The refusals exist
(`src/DcaShop.Account/Application/RegisterAccount/RegisterAccountUseCase.cs:44-52`, the address normalised by
`src/DcaShop.Account/Domain/Model/Email.cs:24`), but the registration page words them differently from the story:

| Key | Story's `Then` | What the page shows today (`src/DcaShop.Account/Adapter/Incoming/Web/RegisterPageController.cs:102-103`) |
| --- | --- | --- |
| taken-address-is-refused | "Email is already registered: anna.schmidt@example.com" | "This email address is already registered" |
| taken-address-in-other-capitals-is-refused | "Email is already registered: anna.schmidt@example.com" | "This email address is already registered" |
| second-registration-from-the-same-browser-is-refused | "User already has an account" | "You already have an account." |

The story's texts are the ones the page showed before commit `8585724` ("refactor(account,cart,checkout,inventory):
one refusal wording, no message in a result"), which replaced them deliberately; `docs/architecture/refusal-wording.md:71`
records the current page wording. The replay story was written from the older wording. Which side is correct?

## Options

1. **Change the story to today's wording** — the three `Then` lines become "This email address is already registered"
   (twice) and "You already have an account."; the story stays adopted, nothing is built, tests are mapped/written.
2. **Change the page back to the story's wording** — the story is no longer an adoption (behaviour changes):
   status back to a buildable story, with a `## Changed expectations` line reverting the wording of `8585724`, and
   `docs/architecture/refusal-wording.md` updated; the Java sample's page wording would have to follow (cross-sample sync).
3. **Drop the exact text from the story** — assert only that the page refuses and the visitor stays logged out / keeps
   the first account; weaker, the wording is then covered by no criterion.

## Recommendation

Option 1. The current wording was a deliberate, recent decision (one refusal wording across contexts, recorded in
`docs/architecture/refusal-wording.md`); the replay backlog simply predates it, and an adopted story should describe
what the shop does.

## Answer
answer: 1 — the story carries today's page sentences: "This email address is already registered" (both address scenarios) and "You already have an account.". It stays adopted; the story text is already changed, in both shops alike.
