# May a browser test carry the title of a scenario that is only in a story not yet delivered?

## Question
The happy path is an `e2e` scenario, so its browser test's `DisplayName` is the scenario's title in words:
"Place order with the review open asks for the review". `SharedScenariosTest.EveryBrowserTestIsAScenarioOfThisShopsSpecification`
(`tests/DcaShop.UnitTests/Specification/SharedScenariosTest.cs:43`) runs in the unit suite, which the profile's `required:`
runs at every gate, and fails for any browser title not in `product/spec/**/scenarios.md`. The spec is written only by the
delivering gate, after build and tidy — so from the test stage on, the build and tidy gates cannot be green. Putting the title
into `TitledAfterTheSharedSpecification` (line 25) passes until delivery and then fails at line 45 ("the list only shrinks").
No story has met this yet: the test arrived in 39d1acb/96e95f8, after the last delivered story with a browser test.
Changing what an existing test checks is not this stage's call.

## Options
- a: `SharedScenariosTest` also reads the scenarios of stories not delivered yet (`product/epics/**/story.md`, status other
  than `delivered`/`superseded`); a browser test may carry such a title until delivery moves it into the spec (changes a test;
  done in this story's test stage, the same change due in the Java twin's counterpart, if it has one).
- b: The pipeline merges the story's spec delta into `product/spec` at the test gate instead of at delivery (a change to
  the dca-factory gate in `dca-marketplace`, not to this project; this story waits for it).
- c: The happy path is planned at `integration (adapter: ConfirmationPageController)` for this story, no browser test
  (departs from the plan rule "the happy path gets e2e").

## Recommendation
a — it closes the gap at the project's own check for every later story, keeps the happy path in the browser, and needs
nothing from the pipeline.

## Answer
answer: SharedScenariosTest also knows the titles of the stories not yet delivered (their `####` criteria, title = Title line else the key in words); the spec stays the only source for the Test-line and duplicate checks. Fixed on main in 2ea4aaa; nothing changes in this story — run the stage again as it is.
