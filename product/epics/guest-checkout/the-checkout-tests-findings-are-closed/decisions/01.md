# What backs renaming `PaymentReferenceTest` to `CheckoutReferenceTest` in a task?

## Question
The plan renames the test class after the checkout reference it tests (findings row
each-payment-names-its-checkout#1): `tests/DcaShop.IntegrationTests/PaymentReferenceTest.cs` is `removed`,
`tests/DcaShop.IntegrationTests/CheckoutReferenceTest.cs` is `new` with the same four tests. The build gate cannot
pass either way: with the old file there, `plan-files` refuses (planned removed, still there); with it gone,
`tests-kept` refuses (an earlier test removed, and the plan has no `## Changed tests` row backing it). Integrate's
`main-tests` check refused the removal earlier for the same reason. A task has no `tests.md`, so no
`## Moved tests` table carries the rename either. How is the rename backed — or does it stay?

## Options
- a: The plan gains `## Changed tests` with the row
  `| tests/DcaShop.IntegrationTests/PaymentReferenceTest.cs | renamed to CheckoutReferenceTest, tests unchanged — findings row each-payment-names-its-checkout#1 |`;
  the build removes the old file. Costs a plan re-run; integrate's `main-tests` must accept the same backing.
- b: The rename is dropped from this task: `PaymentReferenceTest.cs` stays, `CheckoutReferenceTest.cs` goes, the
  spec's four `Test:` lines name `PaymentReferenceTest` again; the findings row stays open for a story of its own.
- c: Both files stay (integrate's state) and the plan's `removed` line is withdrawn — the four tests then run twice
  under two class names.

## Recommendation
a — the rename is exactly what the findings row asks and changes no assertion; the plan's missing backing row is
the only gap, and a plan line is where the gate looks for it.

Evidence: build gate reports in `.dca-factory/evidence/the-checkout-tests-findings-are-closed/`;
`diff` of the two files shows only the class name and constructor differ; plan `## Files` lines 27–28.
