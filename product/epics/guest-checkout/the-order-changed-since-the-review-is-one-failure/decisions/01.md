# Three existing tests assert the type the task removes — may they name the merged one?

## Question
The task merges `PriceChangedSinceReviewException` into `OrderChangedSinceReviewException`. Three tests that existed
before the task assert the removed type by name; without the type they do not compile, and a task may not change a
test that existed before it (`tests-kept`) unless a decision of this story backs the plan's `## Changed tests` row.
The assertions and the values they expect would stay; only the type's name — and the property the price test reads —
would follow the merge:

- `tests/DcaShop.UnitTests/Checkout/CheckoutSessionTodaysPricesTest.cs:71` expects `PriceChangedSinceReviewException`
  and reads its `ProductName` (line 74, expected value `"Domain-Driven Design"` kept); line 89 already expects
  `OrderChangedSinceReviewException`.
- `tests/DcaShop.UnitTests/Specification/CheckoutSpecificationTest.cs:82` expects `PriceChangedSinceReviewException`
  for the vector `checkout.confirm.price-changed`.
- `tests/DcaShop.IntegrationTests/ReviewFingerprintTest.cs:51` expects `PriceChangedSinceReviewException` from
  `ConfirmCheckout` after a price change.

The Java shop's one type (`CheckoutChangedSinceReviewException`, to be renamed by its own task) carries the product as
an optional `productWithChangedPrice`; the plan mirrors that shape, so the property name changes with the type.

## Options
- a: The three tests name `OrderChangedSinceReviewException` where they named the removed type, and the price test
  reads `ProductWithChangedPrice` instead of `ProductName`; every other line, assertion and expected value stays
  (changes a test). The plan lists the three files under `## Changed tests` citing this decision.
- b: `PriceChangedSinceReviewException` stays as a type — a subclass of `OrderChangedSinceReviewException` — so no
  test changes; the refusal is not one failure, and the shape differs from the Java shop's.
- c: The task is superseded and written anew as a story with `## Changed expectations` naming the three tests; the same
  change, one more round through the backlog.

## Recommendation
a — the tests keep what they expect (a refusal that names the product, the state unchanged) and only follow the
type's name, which is what the task asks for; b keeps two types the task says are one, c delays the same change.
