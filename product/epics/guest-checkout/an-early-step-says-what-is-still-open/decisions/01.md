# After the hand reset of the rounds, how may the test stage prove its tests red when the code is already in the tree?

## Question
The document gate refused the story with `story-pass`: the stage files were from an earlier pass
(`.dca-factory/evidence/an-early-step-says-what-is-still-open/gate-document.211038.txt`). The rounds were then
reset by hand (`journal.tsv` seq 117, `rounds-reset by=--from`). That removed tests.md through document.md but
left the earlier pass's production change in the worktree
(`src/DcaShop.Checkout/Adapter/Incoming/Web/CheckoutRoutes.cs:24-35`, `CheckoutPageController.cs`).

The test gate now refuses `tests-red`, three times: both mapped tests pass before the build stage, because the
code they test is already there. Break patches under `runs/an-early-step-says-what-is-still-open/breaks/` (each
drops `?notice=`, `CheckoutRoutes.cs:35`; `git apply --check` passes) are not taken. The contract applies a break
only "in a round the judge sent back (`back: test`)", and after the reset this round is not one.

The tests are unchanged since they were seen red (`.tests-red`, 23:02). The judge's one defect (`BasePage`
helper) is already fixed in the tree. The test stage may not revert production code, and its shell has no
command that does.

## Options
- a: Restart the story from the judge, or let the runner treat this pass as `back: test`, so the break patches
  count. Nothing in the tree changes, and the existing `.tests-red` proof stays valid.
- b: Revert the production files (`CheckoutPageController.cs`, `CheckoutRoutes.cs`) to `base-tree` before the
  test stage runs again. The test, build and tidy stages then run as a true fresh pass, and the build re-applies
  the same change.
- c: Accept the current tree and the passing `test` gate of the earlier pass (`journal.tsv` seq 87), and rerun
  only judge and document.

## Recommendation
a. The judge's defect is fixed, the code is unchanged and red was already proven. A pass that counts the breaks
proves the same thing without throwing the build away.

## Answer
answer: b — the two production files go back to the base before the test stage runs again; the tests stay. The build then applies the change anew, the valid codes as one enum in the incoming web adapter (product/tech.md, Runtime).
