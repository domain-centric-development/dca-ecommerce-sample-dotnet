# Two flaky cases outside the story keep the full suite red — how does the story get past the gate?

## Question
The story's own tests are green, as are the architecture suite and the formatter, and the integration and browser
suites each pass when run on their own. The gate's full `dotnet test` run (all projects at once) fails
on one of two cases outside this story's footprint:

- `ProviderPaymentTest.ARefusedPaymentKeepsTheCustomerAtThePaymentStepWithTheRefusalText`: expected "The payment was
  refused…", got "The payment provider is not available right now…". The stub's 402 answer comes later than the
  2-second `PaymentProviderOptions.Timeout` while every suite runs at once. This happened in 4 of the last 5 full runs.
- `EmbeddingPolicyE2eTest` "A foreign site cannot add to the cart": Playwright reports "Navigation to …/cart is
  interrupted by another navigation to …/cart/add-product". `PressAddToCartOnTheFirstProductInTheFrameAsync` returns
  before the add-to-cart navigation has settled.

The same two cases are red in the evidence of at least eight other stories, e.g. `stock-checks-answer-on-the-page`,
`cart-list-spells-the-status`, `choose-how-to-pay` and `a-site-of-the-shops-own-can-embed-it`. The story changes
neither the checkout nor the product page. Fixing either case changes a test or checkout code outside this story,
which a tidy stage may not do.

## Options
- a: Fix both flakes on main by hand, then run this story's tidy stage again as it is.
    The payment test gives its shop a longer provider timeout through `Checkout:PaymentProvider:Timeout` (it already
    sets the base URL that way). The embedding test waits for the add-to-cart navigation to finish before it points
    the frame elsewhere. Costs one small fix commit on main and stops the same refusal in every other story.
- b: Run the tidy gate again until the full run happens to be green. Costs nothing up front, but it failed in 4 of 5
    runs and leaves the next story with the same problem.
- c: Write a separate backlog story for the two flakes and hold this story until it is delivered.

## Recommendation
a — The cause is in two existing tests and is the same for every story; a fix on main closes it at the source, and
this story needs no change.
