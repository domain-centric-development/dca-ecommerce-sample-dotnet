# How does a story's new browser test pass `SharedScenariosTest` before its scenario is in `product/spec`?

## Question

The build gate's `test` suite (`dotnet test tests/DcaShop.UnitTests`) fails on
`SharedScenariosTest.EveryBrowserTestIsAScenarioOfThisShopsSpecification`: the new browser test "Remove takes the line
out" (`tests/DcaShop.E2eTests/RemoveFromCartE2eTest.cs:12`) is not a scenario title in `product/spec/**/scenarios.md`.
`product/spec` is written only by the gate that delivers the story, and the test gate requires the happy path at the e2e
level. So every story with a new browser test fails the build gate until delivery. This has been the case since commit
96e95f8 emptied `TitledAfterTheSharedSpecification`. Everything else is green: the six criterion tests,
architecture, format.

## Options

1. **The test also reads the stories in delivery.** `SharedScenariosTest` also accepts titles of scenarios that a story
   in `product/epics/**/story.md` with a running state adds (its `#### key` / `Title:` lines). Local to this sample;
   the Java twin's counterpart would need the same.
2. **The pipeline merges the spec delta earlier.** The dca-factory gate makes the plan's `## Spec delta` visible to the
   suite from the build gate on (e.g. a provisional merge into `product/spec` that delivery confirms). Fixes it at the
   source for every project.
3. **A temporary entry in `TitledAfterTheSharedSpecification`.** The build adds "Remove takes the line out" to the
   list, and the document stage (or delivery) takes it off once the spec holds the title. This is a hand step on every
   story, and the list's "only shrinks" rule is broken for a while.
4. **Leave `SharedScenariosTest` out of the gate's `test` command** and run it only on the main line (CI). This weakens
   the commit hook.

## Recommendation

Option 2 fixes the gap where it comes from, in the pipeline that owns the spec. Until it lands, option 1 unblocks this
story and the next ones without a hand step.

## Answer
answer: SharedScenariosTest also knows the titles of the stories not yet delivered (their `####` criteria, title = Title line else the key in words); the spec stays the only source for the Test-line and duplicate checks. Fixed on main in 2ea4aaa; nothing changes in this story — run the stage again as it is.
