# The .NET shop accepts an image URL of 2001 characters — adopt the story without that scenario, or change the shop?

## Question
The story is `status: adopted`, so it may only describe behaviour the shop already has. Six of its seven scenarios
hold on today's code. `an-overlong-image-url-is-refused` does not: when staff create a product with an `imageUrl` of
2001 characters, the .NET shop answers 201, not 400.

Evidence:
- `src/DcaShop.Product/Domain/Model/ImageUrl.cs:8` — the constructor takes any length (`Value = value ?? string.Empty`), with no guard.
- `src/DcaShop.Product/Adapter/Incoming/Api/CreateProductRequest.cs:9` — `string? ImageUrl` has no `[MaxLength]`.
- `src/DcaShop.Product/Application/CreateProduct/CreateProductUseCase.cs:43` — `ImageUrl.Of(command.ImageUrl)` passes the value straight through.
- The Java sample refuses it: `dca-ecommerce-sample-java/…/product/domain/model/ImageUrl.java:12` throws "Image URL cannot exceed 2000 characters". The two shops disagree.
- The other six scenarios hold: `ProductApiExceptionHandler.cs:53-55` (409 with the duplicate wording), `:70-72` (400 "Unacceptable value", no detail), `Sku.cs:31`, `ProductName.cs:10-18`, `ProductDescription.cs:11`, and `[Required]` on `CreateProductRequest.Name` for the blank name.

A plan stage cannot add a guard to an adopted story. Making the shop refuse the value changes agreed behaviour (today the
value is accepted), so the person has to decide.

## Options
- a: The Java shop is right. Take `an-overlong-image-url-is-refused` out of this story so it can be adopted as it is,
  and write a change story that adds the 2000-character guard to `ImageUrl`, as `created-product-answers-with-its-price`
  did for `staff-create-a-product-through-the-api-01`. Two story edits, one new story; no test changes.
- b: Turn this story into a change story (`status` other than `adopted`). The pipeline then builds the `ImageUrl` guard
  here and adopts the other six scenarios as characterizations. One story, but adopted and changed behaviour sit together in it.
- c: The .NET shop is right and an image URL has no length limit. Remove the scenario and the "image URL" half of its
  rule from the story, and bring the Java sample in line separately.

## Recommendation
a: it matches the earlier answer `staff-create-a-product-through-the-api-01` ("the Java shop is right", fixed by a change
story) and keeps this story's adoption free of new code.

## Answer
answer: a — the Java shop is right. The .NET shop is brought in line by a change story, image-url-is-held-to-2000-characters, which this story depends on. This story stays adopted as written, all seven scenarios.
