# How is the-cart-page#2 closed, which this task cannot change?

## Question
The task closes findings row the-cart-page#2: the example of criterion `vat-is-rounded-half-up`
(`product/epics/fill-a-cart/the-cart-page/story.md:52`, `product/spec/cart/shopping/scenarios.md:96`) cannot tell
half-up from half-to-even. The row's fix is to add an example that lands exactly on half a cent, or to rename the
criterion to what it proves. Neither fits this task. No example can exist: the cart's contained VAT is
`gross − gross / 1.19` (`src/DcaShop.Cart/Domain/Model/EnrichedCart.cs:36-38`), and 19/119 of a whole number of cents
never ends on exactly half a cent. So both rounding rules always give the same answer on the cart page. Renaming the
criterion changes the spec, which only a delivering story writes. It also changes the scenario's title, which both
browser suites carry, and `check-shop-spec.py` keeps the two shops' spec equal. A task can do neither. The other 17
rows are planned (see `plan.md`) and wait only for this answer.

## Options
- a: Take the row out of this task's `closes:` and give it a story of its own, in both shops, that renames the
  criterion to what it proves (for example `vat-is-rounded-to-the-cent`). The scenario title then follows in both suites.
- b: Take the row out of `closes:` and set it to `wont-fix`. The key overclaims, but no example can show the
  difference, and the rounding rule stays stated in `Money` (`product/spec/cart/glossary.md:318`).
- c: Keep the row in this task, and let the build edit only the delivered story's text, `story.md:52`. The spec and
  both suites keep the old key, so the story's text and the spec disagree.

## Recommendation
a: the criterion claims a rule that no cart-page example can show, and only a story that runs in both shops can
rename it while keeping the two shops' spec equal.
