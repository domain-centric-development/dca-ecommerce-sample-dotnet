# How does this story's new end-user test pass `SharedScenariosTest` before its scenario is in `product/spec`?

## Question
The production change is done and both mapped tests are green (`DcaShop.E2eTests.CartApiE2eTest#ReadingTheActiveCartOfACustomerWithoutOneIsNotFound`,
`DcaShop.IntegrationTests.CartApiTest#ReadingTheActiveCartLeavesNoCartBehindSoOpeningOneIsCreated`); architecture and
format pass. The build gate still fails on the required unit suite:
`SharedScenariosTest.EveryBrowserTestIsAScenarioOfThisShopsSpecification` (`tests/DcaShop.UnitTests/Specification/SharedScenariosTest.cs:43`)
finds the title "No active cart is not found" (`tests/DcaShop.E2eTests/CartApiE2eTest.cs:16`) in no
`product/spec/**/scenarios.md`. Only the delivering gate writes `product/spec`, and the test gate demands the happy path
at e2e with that title, so the story cannot pass build. It is the same gap as `remove-a-line-from-the-cart-01` and
`registration-says-the-account-was-created-01`, still unanswered; one answer should settle all three.

## Options
- a) `SharedScenariosTest` also accepts the scenario titles of stories under `product/epics/**/story.md` not yet
  delivered. This changes an existing test once and is local to the sample (the Java twin needs the same).
- b) The factory's build/tidy gates merge the plan's `## Spec delta` into a scratch `product/spec` before the required
  suites run. This is a change in `dca-marketplace`, and it fixes the gap for every project.
- c) Add a temporary entry to `TitledAfterTheSharedSpecification`. Not recommended: its "only shrinks" check (line 45)
  fails the moment the scenario lands, so every story needs a hand step.

## Recommendation
b) at the source, with a) as the stop-gap until it lands. Answer the same way as the two sibling records.

answer: SharedScenariosTest also knows the titles of the stories not yet delivered (their `####` criteria, title = Title line else the key in words); the spec stays the only source for the Test-line and duplicate checks.
