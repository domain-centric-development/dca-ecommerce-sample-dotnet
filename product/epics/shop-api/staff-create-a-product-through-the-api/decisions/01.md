# Two scenarios of this adopted story do not hold on today's code — build them first, or take them out?

## Question

The story is `status: adopted`, so nothing is built and every scenario must already hold. Two do not:

1. **staff-create-a-product** — its last `And` wants the 201 body to carry `price` 14.99 and `currency` "EUR".
   The create answer sends both as `null`: `ProductDtoConverter.ToDto(CreateProductResult, CreateProductCommand)`
   passes `null, null` for price and currency (`src/DcaShop.Product/Adapter/Incoming/Api/ProductDtoConverter.cs:26`),
   by design ("price and stock … are not known yet", same file line 13), although the command carries both
   (`src/DcaShop.Product/Adapter/Incoming/Api/ProductResource.cs:55`). The status 201, `id`, `sku`, `name` and
   `category` hold.
2. **a-product-page-without-description** — the page should read "No description available.". The product page
   renders no description block at all when the description is empty
   (`src/DcaShop.Web/Views/Product/Detail.cshtml:35`); the text appears nowhere in `src/`.

The other five scenarios hold (`ProductResource.cs:53`, `Views/Product/Catalog.cshtml:22`,
`ShopIdentityAuthenticationHandler.cs:94` and `:108`; `ApiFlowTest.TheCatalogIsPublicButCreatingAProductNeedsStaff`
asserts their statuses). The sibling `creating-a-product-holds-its-price` (adopted, depends on this story) has the
same gap: `a-price-is-rounded-half-up-to-cents` wants `price` 15.00 in the 201 body.

## Options

a. **A story of its own first** (as `read-the-catalogue-through-the-api-01` was answered): a building story — the
   create answer carries the price and currency it was given, and the product page says "No description
   available." without a description — delivered before this one; this story is then adopted as written.
b. **Turn this story into a building story** (`status` other than `adopted`): it builds the two gaps itself and
   adopts the rest through characterization tests.
c. **Take the two clauses out of this story**: drop the body's `price`/`currency` from `staff-create-a-product`
   and the scenario `a-product-page-without-description`; adopt what remains.

## Recommendation

a — it keeps adoption honest (nothing built under an adopted story), follows the precedent of
`read-the-catalogue-through-the-api-01`, and the same new story can also close the gap
`creating-a-product-holds-its-price` will hit (the rounded price in the 201 body).

## Answer
answer: a — the Java shop is right. The .NET shop is brought in line by a change story, created-product-answers-with-its-price (staff-create-a-product and a-product-page-without-description as written), which this story and creating-a-product-holds-its-price depend on. This story stays adopted as written.
