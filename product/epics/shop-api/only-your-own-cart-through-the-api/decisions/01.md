# The story is `adopted`, but the staff cart list spells `status` "Active", not "ACTIVE" — how do we go on?

## Question

Adopt mode builds nothing; a scenario the code does not show is not adoptable. One scenario differs from the code:

| Scenario | The story says | The code does | Evidence |
| --- | --- | --- | --- |
| `staff-list-every-cart` | each listed cart has `status` "ACTIVE" | `status` "Active" — the list passes `CartStatus.ToString()` through unchanged | `src/DcaShop.Cart/Application/Operations/GetAllCarts/GetAllCartsUseCase.cs:28`, `src/DcaShop.Cart/Adapter/Incoming/Api/ShoppingCartDtoConverter.cs:35` |

`cart-api-answers-as-the-reference` brought the single-cart answer to "ACTIVE"
(`src/DcaShop.Cart/Adapter/Incoming/Api/ShoppingCartDtoConverter.cs:21`, `ToUpperInvariant()`), but not the list.
Everything else in that scenario holds (`cartId`, `customerId`, `itemCount` 1, `total` 109.98, `currency` "EUR").

The other seven scenarios hold on today's code: the foreign-cart 404s (`src/DcaShop.Cart/Adapter/Incoming/Api/ShoppingCartResource.cs:88`,
`:99`, `:115`, `:132`), the 401 with `WWW-Authenticate: Bearer`
(`src/DcaShop.Account/Adapter/Incoming/Security/ShopIdentityAuthenticationHandler.cs:98`), the 403
(`ShoppingCartResource.cs:77`), and a fresh anonymous identity per tokenless call (`ShopIdentityAuthenticationHandler.cs:185`).

## Options

1. **Split, as for `open-and-fill-a-cart-through-the-api-01`.** A small change story (`ready`, context cart, feature
   shopping) spells the list's `status` as "ACTIVE" — `## Changed expectations`: "A listed cart's `status` reads
   "Active" now and "ACTIVE" after." This story depends on it and stays adopted as written.
2. **Make this whole story a build story** (`status: ready`). The seven scenarios that hold would get green tests,
   which the test gate refuses — they would have to leave the story anyway.
3. **Reword the scenario to "Active"** and adopt it whole. The list then spells the status differently from the single
   cart and, per the replayed `API-07`, from the Java shop — a determinism gap.

## Recommendation

Option 1. Same gap, same remedy as `open-and-fill-a-cart-through-the-api-01`: the two samples describe one shop, and
one answer of the cart API should not spell a status two ways.

## Answer
answer: 1 — the Java shop is right. The .NET shop is brought in line by a change story, cart-list-spells-the-status, which this story depends on. This story stays adopted as written.
