# The integrate suite needs the scenario in the spec before the adopted story's spec delta is merged — which side moves?

## Question

The judge asked. The story's change is one new browser test, `CreateProductApiE2eTest#TheAnswerCarriesThePriceRoundedHalfUpToCents`,
DisplayName "The answer carries the rounded price". It is the title of the story's own criterion key in words. It is
green, and it turns red under its break. The integrate gate (`gate-integrate.154906.txt`) then fails on
`SharedScenariosTest.EveryBrowserTestIsAScenarioOfThisShopsSpecification`
(`tests/DcaShop.UnitTests/Specification/SharedScenariosTest.cs:43`): that test wants every browser test's title to
be a scenario in `product/spec/**/scenarios.md`. The scenario is not there yet. Neither the worktree's nor the main
checkout's `product/spec/product/assortment/scenarios.md` has `the-answer-carries-the-rounded-price`. The integrate
gate says "spec-delta — 1 added", but it runs the suite without that delta. For an adopted story, the journal goes
judge → adopt gate → integrate, with no document stage in between. No stage of this story may write the spec
("written only by the gate that delivers"), so another judge `pass` sends the story back into the same failure.

## Options

a. The pipeline merges an adopted story's spec delta into the tree before the integrate suite runs, or runs
   `SharedScenariosTest` against the merged spec. The story stays as it is. This is a pipeline fix in
   `dca-marketplace/plugins/dca-factory`, outside this story.
b. The plan maps the criterion to an integration test (`tests/DcaShop.IntegrationTests`, an HTTP client against the
   `WebApplicationFactory`) instead of a browser test. `SharedScenariosTest` does not bind integration tests. The
   level then differs from the Java twin's `ProductCreationApiE2ETest`, which is a determinism gap between the twins.
c. `SharedScenariosTest` also counts the open stories' criteria as scenarios. This loosens a check that is there
   to keep both suites on the spec's titles.

## Recommendation

a. The test and the spec are both right. Only the order in which the pipeline merges them is wrong, and every
later adopted story that brings a browser test will hit the same failure.
