# The story is `adopted`, but a price of 0.001 is refused with another title than the story names — how do we go on?

## Question

Adopt mode builds nothing; a scenario the code does not show is not adoptable. One scenario differs from the code:

| Scenario | The story says | The code does | Evidence |
| --- | --- | --- | --- |
| `a-price-that-rounds-to-zero-is-refused` | `400`, problem title "Unacceptable value", no detail | `400` from `[ApiController]` model validation before the use case runs: `[Range(0.01, …)]` refuses 0.001, the body is a validation problem with title "One or more validation errors occurred." and an `errors` member | `src/DcaShop.Product/Adapter/Incoming/Api/CreateProductRequest.cs:10`; "Unacceptable value" is only written for an `ArgumentException` (`src/DcaShop.Product/Adapter/Incoming/Api/ProductApiExceptionHandler.cs:72`), which `Price` would raise (`src/DcaShop.SharedKernel/Domain/Model/Price.cs:11`) if the request reached it |

The other six scenarios hold: rounding half up in `src/DcaShop.SharedKernel/Domain/Model/Money.cs:24`, the upper
bound in `Money.cs:22` (→ `ArgumentException` → "Unacceptable value", no detail), price zero and negative stock refused
`400` by `CreateProductRequest.cs:10-12` (their body is out of scope), stock zero accepted (`Product.cs:63` refuses only
below zero). No existing test asserts any of the seven; `ApiProblemDetailTest.AValueTheModelRefusesIsABadRequest`
(`tests/DcaShop.IntegrationTests/ApiProblemDetailTest.cs:51`) asserts the title for another value.

## Options

1. **Split.** Keep this story `adopted` with the six scenarios the code shows; move
   `a-price-that-rounds-to-zero-is-refused` into a change story (`ready`) that makes the .NET API answer as the Java
   sample does — e.g. the request's lower bound no longer refuses a positive amount below a cent, so `Price` refuses the
   rounded zero and the handler writes "Unacceptable value". This story depends on it.
2. **Make this whole story a build story.** The six scenarios that already hold would get green tests, which the test
   gate refuses — they would have to leave the story anyway.
3. **Reword the scenario to the .NET answer** (title "One or more validation errors occurred.") and adopt it whole. The
   two samples then answer the same request differently — a determinism gap.

## Recommendation

Option 1, as for `open-and-fill-a-cart-through-the-api-01`: the story replays the Java sample's `API-05`, and a .NET API
that answers it differently is the gap to close in code, not to record in the story.

## Answer
answer: 1 — the Java shop is right. The .NET shop is brought in line by a change story, price-rounding-to-zero-is-unacceptable, which this story depends on. This story stays adopted as written.
