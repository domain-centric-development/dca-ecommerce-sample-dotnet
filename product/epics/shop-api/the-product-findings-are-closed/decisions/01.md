# May this task remove the two older price and stock refusal tests that finding #4 calls weaker copies?

## Question
The story closes `an-unusable-product-request-is-a-problem-document#4`, whose fix is "Remove them once the
scenarios' `Test:` lines point to the new tests". The `Test:` lines already point to the new tests
(`product/spec/product/assortment/scenarios.md:140`, `:180`), and the two older tests send the same bodies and
assert a subset of the new ones:

- `tests/DcaShop.IntegrationTests/ProductPriceAndStockRulesTest.cs:25` `APriceOfZeroIsRefusedAndTheCatalogueKeepsItsProducts`
  — status 400 and 21 products; `:112` asserts that and the problem document with `errors.price`.
- `tests/DcaShop.IntegrationTests/ProductPriceAndStockRulesTest.cs:99` `ANegativeInitialStockIsRefusedAndTheCatalogueKeepsItsProducts`
  — status 400 and 21 products; `:131` asserts that and the problem document with `errors.stock`.

A task may not change or remove a test that existed before it (`tests-kept`); the only backing a task can carry is an
answered decision of its own, cited in the plan's `## Changed tests`. So the removal is the person's to authorise.
No behaviour changes either way. The other finding this task closes (`created-product-answers-with-its-price#1`)
touches no test.

## Options
- a: Remove both older tests (changes a test); the plan lists `ProductPriceAndStockRulesTest.cs` under `## Changed tests` citing this record, and finding #4 is closed.
- b: Keep both tests; take `an-unusable-product-request-is-a-problem-document#4` out of the story's `closes:` and set the row `wont-fix`, so the task closes only the view finding.

## Recommendation
a — the newer tests cover every assertion of the older ones with the same requests, so nothing is lost, and the
finding's own fix is exactly this removal.
