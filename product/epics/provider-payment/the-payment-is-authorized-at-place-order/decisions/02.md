# How does the integrate step keep a just-accepted story's spec delta exempt until the delivery commit writes it?

## Question

The integrate gate refused the story on two cases of `tests/DcaShop.UnitTests/Specification/SharedScenariosTest.cs`
(`tests/DcaShop.UnitTests/TestResults/_zuse-2_2026-10-21_17_42_56_net10.0.trx`):
`EveryBrowserTestAScenarioNamesExists` (line 85) names the three retired browser tests that
`product/spec/checkout/payment/scenarios.md` still lists, and `EveryBrowserTestIsAScenarioOfThisShopsSpecification`
(line 52) names the new title "Place Order has the payment provider authorize the total the review showed and opens
the confirmation". Both exemptions (decision 01) hold only while the story is not `delivered`. At integrate the story
already reads `delivered` (the worktree's `product/epics` is now a link to the main checkout's, where the acceptance
wrote it), while the worktree's spec is still the old one: the gate writes the spec delta only in the delivery commit,
after integrate. With the story back at `approved`, both cases are green again (run of 2026-10-21, 4 of 4 passed), so
the build gate cannot show it — the next integrate refuses the same way. No production code takes part; the code of
the story is as the judge passed it.

## Options
- a: Change `SharedScenariosTest` so a delivered story still counts as changing its scenarios until they are in the spec.
  "Landed" read as: every criterion of the story stands in `product/spec` under its title. The test stage changes
  the test (two assertions' exemptions), the build runs again; the rule holds for every story, whatever the pipeline order.
- b: Let the integrate step write the story's spec delta into the worktree before it runs the suites (a pipeline change in `dca-factory`).
  The fix at the source of the order; this story waits for the pipeline release.
- c: Keep the worktree's `product/epics` a copy of the branch's, not a link, during integrate (a pipeline change in `dca-factory`).
  The story then reads `approved` there, as it did for the stories integrated before the link.

## Recommendation
b — the suite should run against the tree the delivery commit produces; a test that guesses whether a delivery has
landed works around an order only the pipeline knows.

## Answer
answer: b — the integrate step writes the story's spec delta into the worktree before it runs the suites, so they run against the tree the delivery commit produces (dca-factory change); the story waits for that release and needs no change of its own.
