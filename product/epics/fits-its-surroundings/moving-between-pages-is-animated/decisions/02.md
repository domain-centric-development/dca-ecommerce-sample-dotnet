# The story's worktree does not contain its dependency `reduced-motion-stills-the-transitions` — refresh it from `main` before the test stage maps the fourth scenario?

## Question
Decision 01 was answered: `reduced-motion-means-no-animation` holds once `reduced-motion-stills-the-transitions` is
delivered, and this story stays adopted with all four scenarios. That story is delivered on `main` (commit `edbf859`,
`feat(portal): Reduced motion stills the page transitions`): it adds `::view-transition-group(*)` and
`::view-transition-image-pair(*)` to the reduced-motion rule in `main.css`, and the E2E test
`ReducedMotionE2eTest#TheProductPageAppearsWithoutAnimationWhenTheVisitorPrefersReducedMotion` with the display name
"Reduced motion means no animation" — this scenario's title.

This story's worktree (branch `story/moving-between-pages-is-animated`) was cut before that: `git log HEAD..main` lists
20 commits, `edbf859` among them, and `main..HEAD` none. Here `main.css:3856` still lacks the group rule and the test
does not exist. In adopt mode the test stage may change no production code, so it can neither map the scenario to a
green test here nor write a second test under the same title (`SharedScenariosTest` refuses two tests for one title).

Also on the merge: `main`'s `BasePage` gained `RecordPageTransitionsAsync` (records `__pageTransitionAnimations`), and
this worktree's uncommitted test change adds a member of the same name with a different record
(`__pageTransition`). After the refresh the test stage would make this story's three tests use one recorder, not two.

## Options
- a: Refresh the worktree from `main` (the runner merges or rebases the story branch; the uncommitted test files stay),
  then rerun the test stage: it maps `reduced-motion-means-no-animation` to the existing `ReducedMotionE2eTest` test,
  unifies the two recorders in `BasePage`, and leaves production code untouched.
- b: Copy `edbf859`'s changes by hand into this worktree (CSS, test, `BasePage`) — identical lines merge cleanly later,
  but the story's diff then shows a production change an adopted story may not make.
- c: Leave `reduced-motion-means-no-animation` uncovered in this story, since the dependency covers it under the same
  title, and adopt with three mapped scenarios.

## Recommendation
a. It is what the dependency was added for; the change belongs to the delivered story, not to this one, and only a
refreshed worktree lets the gate see the scenario green with its existing test.

## Answer
answer: a — refresh the worktree from main and run the test stage again. The worktree's uncommitted test files of the earlier round were set aside by hand (a copy is kept outside the project), so the story branch moves onto main as it is; the test stage maps reduced-motion-means-no-animation to ReducedMotionE2eTest and writes the other three on the one recorder BasePage has on main.
