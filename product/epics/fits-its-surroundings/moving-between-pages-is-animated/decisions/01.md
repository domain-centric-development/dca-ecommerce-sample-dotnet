# Under reduced motion the shop still slides the product image (and every named part) for 250 ms — what does `reduced-motion-means-no-animation` adopt?

## Question
The story is adopted, so each scenario needs a test that is green on today's shop. `reduced-motion-means-no-animation`
says "the product page appears without any animation". Observed in the suite's Chromium with the reduced-motion
preference set, following "View Details" to "Domain-Driven Design": the browser still runs a view transition, with
250 ms group animations on `root`, `site-header`, `site-logo`, `site-footer`, `breadcrumb` and the product image —
the image moves from its card position (x 460, y −215) to its place on the product page (x 64, y 310). Only the fades
are switched off.

Why: `src/DcaShop.Web/wwwroot/css/main.css:3856` switches off `::view-transition-old(*)` and `::view-transition-new(*)`,
but not `::view-transition-group(*)`, and the `*` rule above it does not reach view-transition pseudo-elements. So the
scenario does not hold today, and the test stage may not write a test that asserts less than it says. The same
stylesheet is a copy of the Java sample's, so the Java shop behaves the same.

(Side note, not part of the question: `main.css:3824` styles `::view-transition-group(product-image)`, a name no element
carries — the image runs on the browser's default 250 ms instead of the 0.35 s the rule intends.)

## Options
- a: Reword the scenario to what the shop does today — e.g. "Then the product page appears without the content fading"
  — and keep the story adopted; the test asserts that old and new pictures carry no animation. The movement under
  reduced motion stays, as a known gap, for a later story.
- b: Keep the scenario as written and make the story a build for it (not adopted): the build adds
  `::view-transition-group(*) { animation: none !important; }` (or `@view-transition { navigation: none; }`) under
  `prefers-reduced-motion: reduce`; the test asserts no animation runs at all. Both samples' `main.css` change together.
- c: Take the scenario out of this story and file it as its own story; this story is adopted with three scenarios.

## Recommendation
b, if the story's intent ("spared the motion … does not make me dizzy") is meant: a sliding image is exactly the motion
that preference asks to avoid, and the fix is one CSS rule shared by both samples. If the replay must reproduce today's
shop unchanged, c rather than a — a reworded scenario would write the gap into the spec as agreed behaviour.


## Answer
answer: A story of its own — the scenario holds as written. Both shops get the change story reduced-motion-stills-the-transitions (no view-transition group animates under prefers-reduced-motion), which this story depends on. This story stays adopted as written, all four scenarios.
