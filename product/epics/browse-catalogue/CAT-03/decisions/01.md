# The not-found page's tab title is "Page Not Found", not "domaincentric.commerce". Which side is correct?

## Question

CAT-03 is `status: adopted`, so it may only describe behaviour the shop already has. Its scenario
`not-found-page-has-the-shop-title` says the browser tab title of the not-found page is "domaincentric.commerce".
The shop shows "Page Not Found" there. That scenario cannot be adopted as written. The other three scenarios
match the code. Should the story change, or the shop?

## Evidence

- `src/DcaShop.Web/Views/Error/404.cshtml:1` sets `ViewData["Title"] = "Page Not Found"`.
- `src/DcaShop.Web/Views/Shared/_Layout.cshtml:9` renders `<title>@(ViewData["Title"] ?? "domaincentric.commerce")</title>`.
  The shop name is only the fallback, and the 404 view overrides it.
- `/products/no-such-product` does not match `ProductPageController.Detail` (route `{productId:guid}`,
  `src/DcaShop.Product/Adapter/Incoming/Web/ProductPageController.cs:31`). It falls through to
  `UseStatusCodePagesWithReExecute("/error/{0}")` (`src/DcaShop.Web/Program.cs:86`) and on to
  `ErrorPageController.Show`, which renders the 404 view (`src/DcaShop.Web/Controllers/ErrorPageController.cs:12`).
- Not checked, because it is outside this stage's inputs: the Java sample's 404 template. The views are meant to
  mirror it one to one (AGENTS.md). If the Java template leaves the title at the default, the two samples differ,
  and the root AGENTS.md rule 1 applies: ask which side is correct.

## Options

1. **Correct the story.** The scenario expects "Page Not Found" as the tab title. The story stays adopted, and
   nothing is built.
2. **Correct the shop.** Drop the title from `404.cshtml` so the layout falls back to "domaincentric.commerce".
   This changes behaviour, so the story can no longer be adopted. Either set it to a built status, or make the
   change by hand first (mirroring whatever the Java sample does) and then adopt.
3. **Remove the scenario** from CAT-03 and adopt the other three.

## Recommendation

First check which title the Java sample's not-found page shows, since the views are meant to be one-to-one
mirrors. If Java shows "domaincentric.commerce", take option 2 as a by-hand parity fix. If Java shows
"Page Not Found", take option 1, because the backlog line is the only thing that is wrong.

## Answer
answer: The code is wrong. The Java shop sets no title on its not-found page, so the layout shows "domaincentric.commerce"; the .NET shop is brought in line by a change story of its own, not-found-title, which CAT-03 depends on. CAT-03 stays adopted as written and is adopted once that story is delivered.
