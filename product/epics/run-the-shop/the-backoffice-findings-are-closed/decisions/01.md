# May the back-office header test drop its own form helper, and with it the helper's token check?

## Question
The one row this task closes (the-back-office-header-is-the-operators#1) asks to delete the private `Form` helper of `tests/DcaShop.IntegrationTests/BackofficeHeaderTest.cs:78` and call the shared `Forms.Submission` (`tests/DcaShop.IntegrationTests/Forms.cs:14`) instead. The helper carries an assertion line — `Assert.False(string.IsNullOrEmpty(token), "the form carries an antiforgery token")` — and deleting it removes that line from a test file that existed before the task. The gate's `tests-kept` reads that as a changed expectation, which only a person's word backs; a task has no `## Changed expectations`. The same check still runs, word for word, inside `Forms.Submission` (`Forms.cs:19`, message "the page carries …"); the `[Fact]`'s own assertions do not change. The worktree already holds the change.

## Options
- a: The test drops its helper and posts through `Forms.Submission`; this answer backs the plan's `## Changed tests` row, and the build runs again.
- b: The row is set to wont-fix and the test keeps its own copy of the helper.

## Recommendation
a — it is exactly the fix the finding names, the token check survives in the shared helper, and no assertion of the test itself changes.
