# The log's type labels no longer all end in "Event" — what does `EventLogShowsPublishedEvents` assert?

## Question
The story lists the delivery of Checkout's own domain event `CheckoutConfirmed` to its reaction
`CheckoutConfirmedEventConsumer`. The log labels an entry with the event type's short name
(`src/DcaShop.Backoffice/Application/Shared/IEventPublicationLogStore.cs:30`), so the new entry reads
`CheckoutConfirmed` — as the Java shop's registry lists it. The existing browser test
`tests/DcaShop.E2eTests/BackofficeE2eTest.cs:46` (`EventLogShowsPublishedEvents`, scenario
`log-lists-the-events-published-at-start-up`) asserts that every type label ends with "Event". It shares the
suite's shop with the tests that place orders, so once this story is built it fails whenever an order was placed
before it reads the log — and always against a shop that has taken an order (`E2E_BASE_URL`). The spec's clause
reads "every entry shows a type label that names the event" (`product/spec/backoffice/eventlog/scenarios.md:8`);
the suffix is the test's own reading of it, and the Java suite asserts no such suffix. The story has no
`## Changed expectations`, so the plan stage may not change the test.

## Options
- a: The story takes a `## Changed expectations` line for `log-lists-the-events-published-at-start-up`: a type
  label is the event type's short name, with or without an "Event" suffix. The test's assertion becomes "every
  type label is a bare type name — not empty, no namespace" (changes a test; the scenario's text stays).
- b: Keep the assertion and label a domain event's entry with a name ending in "Event" (`CheckoutConfirmedEvent`,
  the integration event it is relayed as, or the suffix added). The label would not be the type the outbox
  holds, differs from the Java shop's log, and misnames a domain event nobody relays.
- c: Keep the assertion and narrow the test to the start-up entries (`ProductCreatedEvent`) — changes the test's
  scope and the scenario's "every entry".

## Recommendation
a — `CheckoutConfirmed` is what the story and the Java shop show, and the suffix was never the spec's; the
assertion keeps biting on a label rendered with its namespace or left empty.
