# A story's new browser test is refused by SharedScenariosTest until the delivering gate writes its scenario — which way round?

## Question
The build gate runs the unit suite, and `tests/DcaShop.UnitTests/Specification/SharedScenariosTest.cs:43` refuses every
browser test whose display name is not a scenario title in `product/spec/**/scenarios.md`. The story's happy path is a
browser test (`tests/DcaShop.E2eTests/GuestCartTakeOverE2eTest.cs`, "Continue takes the guest cart over", as the test
gate requires), but `product/spec` is written only by the gate that delivers the story (AGENTS.md, "Delivery pipeline").
So the build gate cannot pass for any story that adds a browser test; this is the first since the exception list was
emptied (96e95f8). Everything else in the build gate is green (20 checks, the whole browser suite 96/96 by hand). A
build stage may not change that test or write the spec, so it asks.

## Options
- a: `SharedScenariosTest` also accepts the scenario titles of stories not yet delivered (`product/epics/**/story.md`
  whose status is before delivered); the delivering gate's spec merge then makes them spec titles (changes a test,
  in the project; the Java twin's equivalent check alike).
- b: the build stage of such a story writes its scenarios into `product/spec/<context>/<feature>/scenarios.md` itself
  (here `cart/cartrecovery`), ahead of the gate — the spec then holds a scenario before it is delivered.
- c: the story's title goes onto `TitledAfterTheSharedSpecification` until delivery (changes a test; against "the list
  only shrinks").

## Recommendation
a — it keeps the spec written only on delivery and lets the check bind the browser suite to scenarios someone wrote;
the rule then holds for every later story with a browser test, in both shops.

## Answer
answer: SharedScenariosTest also knows the titles of the stories not yet delivered (their `####` criteria, title = Title line else the key in words); the spec stays the only source for the Test-line and duplicate checks. Fixed on main in 2ea4aaa; nothing changes in this story — run the stage again as it is.
